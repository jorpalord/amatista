# HISTORY.md — Bitácora del experimento composed-tools

> Herramientas compuestas: recetas declarativas (nunca código) que encadenan tools reales del catálogo, con aprobación de creación y una aprobación única por corrida sobre el alcance real. Log append-only, entrada más reciente arriba.

| Paso | Fecha | Resumen | Archivos | Estado |
|---|---|---|---|---|
| 3 | 2026-09-23 | **Implementación real v1.** Puente de DeepSeek PWA traído con `git cherry-pick -n bcc3a2a` (staged, separable del resto). Nuevo `composed-tools.ts` (validación, plantillas sin `eval`, adaptadores fijos, `RecipeRunGrant`, almacenamiento firmado con HMAC) + ejecutor en `ToolRegistry` (descubrimiento con las 3 capas de `explore` + `sessionId`, plan congelado con vistas previas exactas, aprobación única, ejecución con `ctx.refresh()` por paso). Diferencias con el diseño, todas por hallazgos reales: el grant verifica en el momento del `confirm()` (`revert_file` hace un `await` antes de leer el disco), la creación usa `hardConfirm`, las recetas quedan firmadas (un `write_file` podía editarlas sin aprobación), pre-chequeo TOCTOU al armar el plan, y el adaptador de `search_files` trata "exactamente 200" como recortado. **Verificado real: 7/7 puntos + DeepSeek PWA** (Gemini API por el camino nativo; DeepSeek API sin saldo, `402`), más 48/48 en la lógica pura. Incidentes documentados: bug previo de Gemini ("turno sin texto", ajeno, propuesto como tarea aparte) y un `503` transitorio. `npm run typecheck`/`npm run build` limpios. | `src/main/composed-tools.ts` (nuevo), `src/main/tool-registry.ts`, `src/main/runtime-state.ts`, `src/main/ipc-agent.ts`, `src/main/api-agent-runtime.ts`, `src/main/deepseek-pwa-runtime.ts` | Completo, verificado real; sin commit |
| 2 | 2026-09-23 | Segunda pasada de diseño (decisión del usuario): **una aprobación por corrida**. Secciones `discover`/`apply` explícitas (el reordenamiento automático es inseguro por dependencias a través del disco), adaptadores de salida (las tools devuelven texto, no listas), `ctx.refresh()` (el `ExecuteContext` es una foto), `RecipeRunGrant` de un solo uso, cobertura limitada a las 4 tools que llaman a `resolveApproval()` exactamente una vez. | `docs/_experiments/composed-tools/CONTRACT.md` | Diseño cerrado |
| 1 | 2026-09-23 | Rama creada desde `master`. Diseño de las 6 tareas (formato, propuesta por runtime, aprobación legible, ejecución, alcance/anidamiento, detector de patrones de Q).
